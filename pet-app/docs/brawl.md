# 寵物大亂鬥 v5

學生在 `/pet` 的「大亂鬥」分頁進入。使用 LF2 式的左右移動、地面前後走位及獨立跳躍高度，戰區向右逐區推進。19 隻非隱藏寵物可出戰，角色造型沿用寵物樂園；每隻都有兩招有不同用途的技能。

貓的技能以鎖定單一敵人及星印連招為主：

- **星影換位（U）**：鎖定前方 230 px 內、地面深度相差最多 48 px 的近敵，短暫閃至其背後並抓擊 18 傷害。命中留下 4 秒星印；換位時有 12 ticks 閃避保護。途中不造成衝撞傷害。沒有有效目標時只向前閃避 100 px。
- **獵星連爪（I）**：鎖定 280 px 內、深度相差最多 70 px 的一名敵人，優先追蹤自己留下的有效星印。沿固定弧線躍起約 110 px，三次抓擊為 7／7／16 傷害；末擊成功命中星印敵人會消耗星印，加強至 22 傷害並擊倒。目標逃出抓擊範圍或倒下時不會重新鎖定其他敵人。沒有目標時只作前躍空揮。

兩招仍耗 20／35 MP，冷卻 3／7 秒。換位命中後可預先輕按 I，收招時會自動銜接連爪。換位能避開朝前的盾牌守備，但場邊無法繞背時仍會被正面防住；連爪的空中高度可避開地面震波。貓的呈現使用紫金星形殘影、敵人頭上的星印、空中追擊姿態與三次交叉爪痕；獨立換位、追擊、抓擊音效。

教學帶玩家逐項完成移動、攻擊、跳躍、防禦及兩招技能。練習場有不反擊的木偶及無限 MP 開關。AI 對戰可選全部 19 種對手，90 秒未分勝負時以剩餘 HP 比例判定。所有模式（教學、練習、AI、闖關及同學對戰）皆需持有該角色，不再提供借用。未擁有角色只可預覽招式及前往商店購買。教學、練習及 AI 不發養成獎勵。

闖關必須持有對應寵物。高階寵物也能出戰，但戰鬥固定使用初階造型及戰鬥數值；全部招式開放。每關包括 6／8／10 隻敵人的三波戰區及一場首領戰，同場一般敵人上限為 3／4／6。戰區清空後向右進入下一區，恢復 20 HP／20 MP。

| --- | --- | --- | --- |
| 輕鬆 | 80%／65% | 1 | 54 ticks |
| 標準 | 100%／100% | 2 | 42 ticks |

任何難度通關可解鎖下一關；同一關通過標準難度才能挑戰該關的挑戰難度。每局最多 10 分鐘模擬時間。單局首次倒下可免費重試目前波次，HP、MP、防禦及技能冷卻回滿／重設；第二次倒下結束，或選擇立即結束。失敗不扣金幣或原有 XP。

勝利得一星、沒有波次重試再得一星、五分鐘內及至少 40% HP 完成再得一星。保存每關每難度的最高星數、最短時間及通關次數。

## 操作及畫面

- WASD／方向鍵：地面移動；Shift：跑步，或雙按左右方向。
- J：攻擊，按住可完成三連段；跑動時攻擊會衝擊，跳躍後攻擊為空中重擊；K：跳躍；L：朝敵人的正面防禦。
- U／I：兩招技能。也接受「防禦 → 朝向 → 攻擊／跳躍」指令，限 24 ticks。
- 技能耗 20／35 MP，冷卻 3／7 秒；MP 每秒恢復 6。防禦減少 80% 傷害，耗防禦值；用盡會破防。
- iPad 橫向以八方向搖桿及五個動作鍵操作，可同時按住不同觸點；觸控取消、失去焦點及暫停會清除按住狀態。極短的按鍵仍保留到下一個模擬 tick。
- Escape／Ⅱ 暫停；轉為直向、切走瀏覽器或頁面隱藏時暫停。直向需要轉回橫向再繼續。
- HUD 每秒更新約 10 次。畫面維持 1280×720 世界比例，在 4:3 畫面保留上下空間。減少動畫設定及系統減少動態偏好會關閉重擊震屏。
- 前景敵人遮住玩家時會暫時淡化，讓玩家仍能看清寵物的位置。

## 連續戰場及戰鬥回饋

每關是 5120×720 的連續世界。鏡頭平滑跟隨角色並向面向方向預留視野，清場後直接跨過戰區邊界，沒有角色移位或逐屏鏡頭跳動。三張原創長卷背景有不同的場景進程，地面影像對齊可行走的 345–565 高度；前景花草與晶石使用獨立深度。

角色與敵人尺寸重新調整，命中提供短暫停頓、白色閃光、火花、傷害數字及重擊震屏。48 格手繪 VFX 包括斬擊、命中、風彈、旋風、地面爆發及塵土；技能另有蓄力、殘影、軌跡及擴散。逐 tick 保存的呈現事件避免慢幀時漏播效果。倒地及起身保護給玩家恢復空間，停頓期间的短按鍵仍會保留。

連擊顯示連續命中數，攻擊命中補充 MP。每第三隻敵人掉落補給，交替為 +25 MP 和 +18 HP；走近即可拾取。這些是單局戰鬥補給，沒有金幣或永久 XP。

音訊使用原創的 17 種合成 Foley，包括近身撞擊、重擊、格擋、揮擊、衝刺、風彈、旋風、踏地、跳落、清場及貓的換位／追擊／抓擊，快取聲音緩衝並以左右聲像定位。Brawl 音樂另有鼓點與和弦。右上角 ♫ 可切換聲音，暫停選單可分別調整音樂及音效。音訊需玩家先點擊操作以符合瀏覽器播放規則。

## 獎勵、API 及資料

以香港日期計，每位學生每日首三次闖關勝利各得 5 金幣及最多 10 XP。XP 發給出戰寵物，和餵食共用該寵物每日 100 XP 上限；剩餘上限不足 10 時只給餘額，XP 滿額仍能領金幣並消耗一次勝利獎勵。之後勝利只記錄通關，不發金幣／XP。結算使用結算當日。

| API | 用途 |
| --- | --- |
| `POST /api/pet/brawl/access` | 免費模式及續關的持有權重新驗證 |
| `GET /api/pet/brawl/catalog` | 版本、角色、關卡、難度及素材 URL |
| `GET /api/pet/brawl/progress` | 最佳紀錄、每日餘額及有效未完成局 |
| `POST /api/pet/brawl/runs` | 驗證擁有權／解鎖；建立種子及設定 |
| `POST /api/pet/brawl/runs/:id/finish` | 提交 `{version, inputs, endTick}`，重播驗證及結算 |
| `POST /api/pet/brawl/runs/:id/abandon` | 放棄未完成局 |

只接受學生登入。開始及結算要求 `Idempotency-Key`。每人最多一局有效闖關，有效期 24 小時。客戶端送入按鍵變化紀錄，不接受客戶端的 HP、獎勵或勝負宣告。伺服器和客戶端使用同一份純模擬，在相同種子及按鍵紀錄下重現相同結果。

驗證在兩個 Node worker 執行，佇列上限 16、單次上限 5 秒。紀錄最多 36,000 ticks，JSON 上限 1 MiB，嚴格驗證按鍵數值、tick 順序及已完成狀態。相同局及紀錄重送回覆原本 receipt；變更已結算紀錄回覆 409。按局識別的帳本不會重複發幣。

JSON 的 `petBrawlRuns`、`petBrawlProgress`、`petBrawlDailyRewards` 使用同步原子保存，並和既有錢包、帳本及寵物數據一起更新。PostgreSQL 對應三張表；同一學生以錢包 row lock 串行交易，包含進度、每日次數、金幣、帳本、XP 及進化。刪除學生時清除相關紀錄。

## 存檔及故障恢復

IndexedDB `buio-pet-brawl` 按學生存 run、規則版本、完整按鍵變化、tick 及結算 key。每五秒、換波、暫停、離頁時保存，寫入依序執行。重新載入會用紀錄重播至原 tick，再暫停等待玩家繼續。

結算前保留完成紀錄，網絡失敗可重試，連線恢復時也會自動嘗試。入帳後停止存檔並等既有寫入完成，再清除紀錄，避免舊 autosave 把已完成局復活。素材未能載入時提供返回大廳操作。裝置儲存拒絕會提示玩家保持頁面開啟。存檔只在同一瀏覽器可恢復；沒有本機紀錄的未完成局可放棄後重開。

`PET_BRAWL_ENABLED=0` 關閉新局；已發出的有效局仍可結算。首次部署會自動建表。日後更改模擬規則必須發布新的版本，並保留舊版本 verifier 至所有有效局到期；新局使用 `brawl-v5`。`legacy/` 保留原始 v1，`legacy/v2/` 保留這次技能修改前的完整 v2 規則。`legacy/v3/` 保留 v3 的完整貓技能及模擬規則。`legacy/v4/` 保留 v4 的完整真人對戰與貓技能規則。五個版本均可恢復存檔、顯示對應技能名稱及在 worker 重播／結算。

## 程式及素材

- `lib/brawl/catalog.mjs`、`simulation.mjs`：共享規則及 60 Hz 純模擬；座標為 1/100 像素整數。
- `lib/brawl/verifier.cjs`、`verifier-worker.mjs`：伺服器重播工作池。
- `repositories/brawl.repo.js`、`routes/brawl.js`：權限、交易、每日獎勵。
- `src/brawl/`：大廳、DOM HUD、多觸點輸入、Phaser Scene、IndexedDB。
- `public/assets/art/brawl/manifest.json`：內容雜湊 WebP，獨立角色圖集及三張背景。由 catalog API 提供，沿用現有 `/pet/assets` 快取政策。
- 素材規格及生成來源見 [素材記錄](../art-source/brawl-v1.md)。房間及穿戴圖集沒有被修改。

## 驗收

```text
npm run build:pet
npm run check:pet-brawl
npm run check:pet-brawl-live
node scripts/test-pet-brawl-v2.mjs
node scripts/test-pet-brawl-cat.mjs
node scripts/test-pet-brawl-quality.mjs
```

瀏覽器測試預設讀取 `pet-app/dist`，也可指定 `PET_APP_DIST_DIR` 指向隔離 build。用隔離 JSON fixture，不改現有學生數據。截圖及報告在 `artifacts/pet-playtest/brawl-v3/`。正常速度的品質測試可用 `PET_BRAWL_CAMPAIGN_FIGHTER=starpatch-cat` 選擇貓完成三關。

模擬／資料測試涵蓋 3 角色 × 3 關 × 3 難度的 27 段合法完整紀錄重播、全部三關至少一次完整勝利、hitbox／跳躍／防禦／技能／重試、解鎖及擁有權、並行和重複結算、每日獎勵、部分 XP 及進化。

Chrome 測試涵蓋 1440×900、1180×820、1024×768、768×1024，真實按鍵和 Chrome 多觸點事件、完成教學、AI 對戰、存檔恢復、闖關首領及完成結算。完整闖關用合法按鍵加速模擬，沒有改 HP、位置或勝負；伺服器獨立重播後才發獎勵。故意中斷第一次結算請求，確認重試只入帳一次。

另涵蓋 catalog／素材載入失敗後重試，以及未孵蛋學生先借角色練習，再返回孵蛋及重建房間畫布的首次使用流程。

目前驗證平台為 Windows Chrome 與 JSON。實體 iPad Safari、PostgreSQL 真實連線及部署環境尚未驗收。


新版原創素材透過內建 image_gen 產生，PNG 原始來源存放在 art-source/imagegen/brawl-v2/，完整提示見 art-source/brawl-v2-prompts.json 及 brawl-v2-effects-prompt.md。scripts/build-pet-brawl-worlds.mjs 僅重新編碼為有內容雜湊的 WebP，保留透明度及圖集幾何。

品質測試以正常 60 Hz 執行三關，不修改 HP、角色位置、種子或勝負；留存實際畫面、音訊量測、靜音測試及完整影片。桌面 Chrome 與 iPad 尺寸／多觸點均有自動驗證；實體 iPad 與 PostgreSQL 執行環境尚未在此工作站驗證。


## 同學對戰

「同學對戰」可邀請目前在寵物樂園前景頁面在線的其他學生，名單顯示姓名及班別。每人須持有自己選擇的已發佈寵物（全部 19 種均可），兩人可各自選擇角色；邀請者選擇場地。邀請通知在房間、收藏、商店等分頁都會出現。正在闖關、練習或推銀仔的學生暫時不能被邀請。

邀請有效 60 秒，可接受、拒絕或由邀請者取消。只有接受時才再次檢查雙方在線狀態、寵物所有權和餘額，並在同一交易中各扣 500 金幣；拒絕、取消、逾時和餘額不足均不扣款。不借用角色，不額外發勝負金幣或 XP。

雙方素材載入完成才開始 3 秒倒數。伺服器以 60 Hz 處理兩人的輸入，以 20 Hz 傳送狀態及特效事件；瀏覽器只傳輸入，不能提交命中、傷害、金幣或勝負。對戰為 90 秒，時間到以剩餘 HP 比例決勝，相同則平手。接收邀請的一方控制第二名角色，HUD、地面指示及連擊顯示均跟隨自己的寵物。

選單只停止自己的輸入，對手仍可繼續操作。開場前取消、素材失敗或準備 30 秒仍未完成，雙方入場費全額退回；開場後投降判負且不退入場費。連線中斷時暫停並保留 20 秒重連機會；重連不再收費。只有一人重新連上時，斷線者判負；雙方均離線時取消並退回雙方費用。

對戰及退款都有持久記錄和每位學生獨立的唯一流水鍵。PostgreSQL 同時鎖定兩個錢包，以 PetBrawlDuelSeats 防止學生重複加入付費對戰；JSON 模式一次保存兩筆扣款，寫入失敗會恢復記憶體資料。伺服器重啟會將未完成的對戰取消並退款；學生帳戶刪除前亦先退回該場雙方費用。

`server.js` 註冊 `/pet-brawl` Socket.IO namespace，共用學生登入 session。事件為 `duel:presence`、`duel:invite`、`duel:reply`、`duel:cancel`、`duel:ready`、`duel:input`、`duel:leave`；通知為 `duel:peers`、`duel:invitation`、`duel:match`、`duel:frame`、`duel:result`。只允許學生及同源或設定允許的來源。每個帳戶同局只有一個分頁可操控。每次重新登入／連線皆重新讀取角色與寵物權限。

目前沿用平台單一即時伺服器的部署方式，邀請和模擬房間在同一個 Node 程序記憶體。不能同時啟動多個對戰伺服器指向同一資料庫；啟動時的復原會退款未完成對戰。擴充至多實例前，須增加分散式房間、共享 presence、伺服器租約及針對失效租約的復原。

### 真人對戰驗證

- `node scripts/test-pet-brawl-pvp.mjs`：隔離 JSON，付款／退款原子性、重複與並行請求、邀請狀態、輸入授權、兩位真人控制、舊 v1–v4 相容、重連／斷線、重啟及刪帳復原。
- `node scripts/test-pet-brawl-pvp-live.mjs`：隔離伺服器和兩個 Chrome 帳戶，實際通知、拒絕、接受、畫面餘額、移動／攻擊／技能、觸控、重新整理、投降及素材失敗退款。預設讀取 `pet-app/dist`；可用 `PET_APP_DIST_DIR` 指定隔離 build。
- 報告及截圖：`artifacts/pet-playtest/brawl-pvp/`。測試不使用正式學生錢包；本機已驗證 JSON 模式，PostgreSQL 和實體 iPad 尚未實測。

### iPad 觸控介面

有粗略觸控指標且畫面寬度至少 768px 時，使用加大的操作區：大廳及邀請按鈕至少高 60px、攻擊 104×104px、跳躍／防禦 88×88px、技能 140×76px、搖桿 156×156px、音效及暫停 64×64px。操作鍵保留至少 14px 間距，中央戰場保持空白。觸控輸入仍支援搖桿與攻擊／跳躍同時按住。1024×768 及 1180×820 的 Chrome 觸控模擬截圖、尺寸及操作驗證在 `artifacts/pet-playtest/brawl-ipad-touch/`。


## 全角色版本與驗收

共 38 招。回旋投射物、扇形彈幕、地面陷阱、延時落雷、固定落點跳躍、護盾反擊、減速苔地、讀心標记、回復、連鎖雷電及影分身都在共享模擬中解算，瀏覽器只繪製狀態與事件。技能有不同 MP 成本、冷卻、蓄力及射程，稀有度不附加隱藏傷害倍率。稀有／史詩主要增加約 20%／45% 的特效尺寸及少量粒子；減少動態效果設定仍適用。

新增 16 隻沿用已發佈的 160px 動畫圖集，按各自宣告的版面讀取幀，排除 idle 中停留時間為零的空幀，加入程序式出拳傾斜、跳躍和技能特效；原有三隻保留專用 256px 格鬥動畫。戰場只載入實際出戰的角色，離開後清除角色圖集與分身。

`POST /api/pet/brawl/access` 在所有免費模式及續關前重新核對學生本人持有的 PetID 與 SpeciesID；闖關建立及 PvP 接受時仍在伺服器檢查持有權。啟動免費模式不扣任何金幣。已有的蛋／領養角色也視為持有；不要求重複購買。大廳提供已擁有／全部／未擁有篩選、可捲動選角清單、稀有度及招式預覽，保留 iPad 大觸控按鈕。

新紀錄使用 `brawl-v5`，v1、v2、v3、v4 的角色表與模擬皆保留原封不動的版本路由，已有闖關仍按原規則重播、續關和驗證。

- `npm run check:pet-brawl-roster`：核對已發佈角色清單；38 招實際傷害或增益、MP、特效狀態、物理有限值、重播；19 角色持有權、跨學生拒絕、圖集及幀界限。
- `npm run check:pet-brawl-roster-live`：隔離 JSON 及實際登入，Chrome 1024×768 觸控；19 角色／38 招載入與渲染、五模式鎖定、API 拒絕，以及孫悟空對雪羽企鵝真人同步、拒絕不扣款和接受各扣 500。
- `check:pet-brawl`、`check:pet-brawl-live`、`check:pet-brawl-pvp`、`check:pet-brawl-pvp-live` 保留闖關與真人對戰的回歸驗證。
- 證據：`artifacts/pet-playtest/brawl-v5/`。以隔離學生資料測試，沒有改動真實學生寵物／錢包；實體 iPad Safari 和 PostgreSQL 尚未實測。
