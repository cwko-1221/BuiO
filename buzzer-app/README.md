# 搶答課堂

老師在平台首頁按「開啟搶答課堂」，設定每題分數（預設 10 分），再開始課堂。可見範圍是選填設定；不設定時，所有已登入學生均可看見及加入，包括課堂建立後才新增的學生帳號。學生從首頁「課堂」選擇加入，系統自動使用已登入的學生帳號及姓名。

老師可加入多條可見範圍規則，每條可選多個班級，以及中文／英文／數學其中一科的多個組別。學生符合任何一條規則即可加入；同一條規則內則須同時符合班級及組別條件。不選班級表示所有班級，不選組別表示全部組別。一條完全不限班級及組別的規則等同不限制。設定時會預覽符合的學生人數；有限制但沒有符合學生時不能開始，預設不限範圍則即使目前名單為空也可開始。

老師口頭提問後按「搶答」，系統先等待所有已加入學生校準時鐘，再確認每人均已收到共同的倒數及開放時間，然後全班同步倒數 3 秒。倒數結束後學生可按中央的大按鈕，老師畫面即時顯示首位成功搶答者。老師按「正確」即把每題分數以 1 分 = 1 金幣加入該學生的 pet-app 錢包；按「錯誤」不發金幣。完成判斷後可開始下一題，也可取消本題或結束整個課堂。

學生必須保持搶答畫面開啟。未能及時確認共同時間、已確認斷線或切到背景時，系統取消尚未搶得回答者的題目，讓老師重新開始。老師可看見正在等待同步的學生姓名。新同學須在題目開始前或完成後加入。

學生右上角的成功搶答數計算搶得答題機會的次數，包含答錯的題目；得到分數只計算老師判為正確的題目。老師可查看學生名單及分數。重新整理或重新啟動伺服器會保留課堂、統計和已發金幣。老師須按「結束課堂」才會關閉加入入口。

## 實作

- `/buzzer`：共用老師／學生介面，使用平台登入。
- `/api/buzzer`：透過共用 `shared/classroom-audience.js` 驗證角色及可見範圍；所有姓名和領幣帳號由伺服器決定。列表、加入、直接讀取、操作及 SSE 均受同一存取檢查保護。
- 新課堂 POST 使用 `audienceRules`，格式為 `[{ classNames: ['5A', '5B'], groupField: 'englishGroup', groupNames: ['A', 'B'] }]`；`[]` 表示所有學生。不同科目可分別加入規則。有限制的課堂在建立時，依當前學年名單保存符合的學生 ID；之後變更名單不會擴大該課堂的存取範圍。
- 舊建立請求未提供 `audienceRules` 而有 `className` 時，仍接受 `className`／`groupField`／`groupName` 並轉換為一條規則；若已提供 `audienceRules`，以新格式為準。已儲存但沒有 `audienceRules` 的舊課堂保留原有 `eligible` 學生限制，不會自動向所有學生開放。老師課堂資料可包含 `audienceRules`。
- 老師設定介面使用 `/shared/classroom-audience-editor.mjs` 及 `/shared/classroom-audience.css`，預設規則為 `[]`。
- SSE 直接推送已儲存的狀態；本機操作不需額外讀取資料庫或等待定時輪詢。每秒心跳檢查連線，重連會重新校準時鐘。
- 每題取 5 次往返校時中延遲最低的一次，以往返中點估算伺服器時間；倒數使用 `performance.now()` 及畫面更新週期，並在題目中固定時間偏移。裝置時間被修改或訊息較晚抵達，不會重新計算三秒倒數。
- 兩階段確認：所有學生完成校時後預先發出共同時間；再等所有學生確認收到。未全部確認就不倒數。預送時間預留至少 1.5 秒，按班內最大往返延遲延長。
- JSON 模式儲存於既有資料庫的 `buzzerSessions`；Postgres 模式自動建立 `BuzzerSessions`，搶答及同步確認各使用一次原子更新，避免先讀取或等待其他課堂的鎖。評分則在同一交易更新課堂、金幣錢包及帳目。
- Postgres `LISTEN/NOTIFY` 推送其他伺服器程序的改動；若資料庫代理不支援通知，使用恢復輪詢。單一程序的直接推送及共同時間排程不依賴此輪詢。
- 每個課堂／題號使用唯一入帳識別碼，防止重複評分、重試或重啟造成重複發幣。

## 驗證

`node --test buzzer-app/tests/audience.test.js` 使用記憶體隔離資料及共用規則 helper，驗證預設全體學生、後新增帳號、多班／多科／多組匹配、建立時名單限制、舊請求及舊課堂相容、空名單、HTTP／SSE 權限、同步確認、同時搶答及金幣只入帳一次。

`node buzzer-app/tests/audience-live.mjs` 使用隔離 JSON 資料及 Chrome，驗證新的可見範圍編輯器、預設全體學生、多班／多科／多組設定、無符合學生的按鈕限制、空名單、POST 格式、存取及 SSE 權限、中英文、手機畫面、同步倒數、金幣入帳及重新整理。不修改現有學生資料。

`npm run check:buzzer-live` 使用隔離 JSON 測試資料及 Chrome，驗證新的共用可見範圍編輯器、課堂入口、三秒倒數、同時搶答、正誤評分、金幣入帳、重新整理／重啟、取消／結束、中英文及手機畫面。截圖位於 `artifacts/buzzer-qa/`，不修改現有學生資料。

`npm run check:buzzer-sync` 另外驗證 30 個學生畫面，模擬裝置時間偏差、不同校時往返延遲及不同狀態訊息延遲，量度每次倒數與按鈕開放的時間差，並驗證兩階段確認、逾時、斷線及背景切換。報告位於 `artifacts/buzzer-qa/sync-report.json`。本機測試的誤差不等於正式網絡的保證；網絡不對稱、渲染停頓、伺服器距離及斷線偵測時間仍影響實際結果，不能承諾物理上的零延遲。搶答順序由伺服器實際收到請求的次序判定，學生提供的點擊時間不作判定依據。

`scripts/test-buzzer-postgres.mjs` 可搭配臨時安裝的 `@electric-sql/pglite`，在 PostgreSQL SQL 引擎中驗證原子搶答、同步確認、班級權限及交易入帳，例如 `node scripts/test-buzzer-postgres.mjs <pglite-package-directory>`。它不使用正式資料庫，亦不測量正式 PostgreSQL 連線延遲。

`node buzzer-app/tests/audience-postgres.mjs <pglite-package-directory>` 另驗證 PostgreSQL 的全體學生存取、後新增帳號姓名、共用規則名單、原子更新的範圍檢查、舊課堂存取及金幣入帳。
