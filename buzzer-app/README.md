# 搶答課堂

老師在平台首頁按「開啟搶答課堂」，選擇班級、全班或中文／英文／數學組別及每題分數，再開始課堂。學生從首頁「課堂」選擇加入，系統自動使用已登入的學生帳號及姓名。

老師口頭提問後按「搶答」，系統先等待所有已加入學生校準時鐘，再確認每人均已收到共同的倒數及開放時間，然後全班同步倒數 3 秒。倒數結束後學生可按中央的大按鈕，老師畫面即時顯示首位成功搶答者。老師按「正確」即把每題分數以 1 分 = 1 金幣加入該學生的 pet-app 錢包；按「錯誤」不發金幣。完成判斷後可開始下一題，也可取消本題或結束整個課堂。

學生必須保持搶答畫面開啟。未能及時確認共同時間、已確認斷線或切到背景時，系統取消尚未搶得回答者的題目，讓老師重新開始。老師可看見正在等待同步的學生姓名。新同學須在題目開始前或完成後加入。

學生右上角的成功搶答數計算搶得答題機會的次數，包含答錯的題目；得到分數只計算老師判為正確的題目。老師可查看學生名單及分數。重新整理或重新啟動伺服器會保留課堂、統計和已發金幣。老師須按「結束課堂」才會關閉加入入口。

## 實作

- `/buzzer`：共用老師／學生介面，使用平台登入。
- `/api/buzzer`：驗證角色、班級及組別；所有姓名和領幣帳號由伺服器決定。
- SSE 直接推送已儲存的狀態；本機操作不需額外讀取資料庫或等待定時輪詢。每秒心跳檢查連線，重連會重新校準時鐘。
- 每題取 5 次往返校時中延遲最低的一次，以往返中點估算伺服器時間；倒數使用 `performance.now()` 及畫面更新週期，並在題目中固定時間偏移。裝置時間被修改或訊息較晚抵達，不會重新計算三秒倒數。
- 兩階段確認：所有學生完成校時後預先發出共同時間；再等所有學生確認收到。未全部確認就不倒數。預送時間預留至少 1.5 秒，按班內最大往返延遲延長。
- JSON 模式儲存於既有資料庫的 `buzzerSessions`；Postgres 模式自動建立 `BuzzerSessions`，搶答及同步確認各使用一次原子更新，避免先讀取或等待其他課堂的鎖。評分則在同一交易更新課堂、金幣錢包及帳目。
- Postgres `LISTEN/NOTIFY` 推送其他伺服器程序的改動；若資料庫代理不支援通知，使用恢復輪詢。單一程序的直接推送及共同時間排程不依賴此輪詢。
- 每個課堂／題號使用唯一入帳識別碼，防止重複評分、重試或重啟造成重複發幣。

## 驗證

`npm run check:buzzer-live` 使用隔離 JSON 測試資料及 Chrome，驗證課堂入口、班級／組別限制、三秒倒數、同時搶答、正誤評分、金幣入帳、重新整理／重啟、取消／結束、中英文及手機畫面。截圖位於 `artifacts/buzzer-qa/`，不修改現有學生資料。

`npm run check:buzzer-sync` 另外驗證 30 個學生畫面，模擬裝置時間偏差、不同校時往返延遲及不同狀態訊息延遲，量度每次倒數與按鈕開放的時間差，並驗證兩階段確認、逾時、斷線及背景切換。報告位於 `artifacts/buzzer-qa/sync-report.json`。本機測試的誤差不等於正式網絡的保證；網絡不對稱、渲染停頓、伺服器距離及斷線偵測時間仍影響實際結果，不能承諾物理上的零延遲。搶答順序由伺服器實際收到請求的次序判定，學生提供的點擊時間不作判定依據。

`scripts/test-buzzer-postgres.mjs` 可搭配臨時安裝的 `@electric-sql/pglite`，在 PostgreSQL SQL 引擎中驗證原子搶答、同步確認、班級權限及交易入帳，例如 `node scripts/test-buzzer-postgres.mjs <pglite-package-directory>`。它不使用正式資料庫，亦不測量正式 PostgreSQL 連線延遲。
