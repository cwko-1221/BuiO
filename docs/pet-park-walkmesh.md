# 樂園發行檢查：腳底碰撞與橋樑

2026-10-24。此文件記錄現有缺陷、替換幾何 API 與尚待整合的發行門檻。**獨立數學測試通過不等於樂園已可發行。**

## 已重現的舊版缺陷

舊 `park-landscape.mjs` 的 `onGardenBridge()` 使用線段距離與 `halfWidth`，實際上允許站立範圍是帶圓頭的膠囊。它沒有寵物腳底半徑，也沒有獨立欄杆碰撞。

北橋實測：

- 中線旁 65 單位的位置 `{ x: 2467.8818633599294, y: 924.9455127776232 }`，`onGardenBridge=true` 且 `walkable=true`。半寬為 68，腳底中心距幾何邊緣只剩 3 單位，仍被接納。
- 橋端外 50 單位的位置 `{ x: 2182.503412476306, y: 771.4438982015408 }` 亦被接納。圓頭範圍與畫中有限的橋板不同。
- 舊 `clearLine()` 每 24 單位取樣。足夠薄的障礙可以完全落在兩個取樣點之間，無法以端點合法推論途中合法。
- 伺服器廣播對座標使用 `Math.round()`，可能把安全腳底推回碰撞邊緣。例如測試橋面上的 `{ x: 500, y: 451.999999 }` 合法，四捨五入為 `{ x: 500, y: 452 }` 即與南欄杆相碰。
- 瀏覽器直接將角色位置插值到最新幀。即使伺服器每個步驟都合法，遺失中間的 volatile 幀後，插值對角線仍可能穿過轉角或欄杆。

舊測試只檢查中線過橋，沒有橋側、圓頭、腳底半徑、薄障礙與插值回歸，因此不能據此接納橋樑品質。

## 新模組與整合合約

`pet-app/lib/park-walkmesh.mjs` 不依賴 Phaser、舊圖片尺寸、伺服器或資料庫。地圖作者提供一份座標資料，同時交給繪圖及此模組。

```js
import { createWalkmesh, rectPolygon } from './park-walkmesh.mjs';

const mesh = createWalkmesh({
  bounds: { x: 0, y: 0, width: 5120, height: 3584 },
  actorRadius: 18,
  water: [/* 可為凹多邊形，或 rect/circle/ellipse */],
  solids: [/* 房屋、花圃、岩石、樹根、池塘、橋欄杆 */],
  bridges: [{
    id: 'north-bridge',
    deck: rectPolygon({ x: 2300, y: 900, width: 440, height: 180 }),
  }],
});

mesh.contains({ x, y });              // 腳底圓盤能否完整站立
mesh.classify({ x, y });              // land/bridge/water/solid/bounds/invalid
mesh.clearSegment(from, to);           // 整段連續掃掠能否通過
mesh.move(from, { x: dx, y: dy });      // 安全移動及滑牆；起點非法則回傳 null
```

Shape 合約：

- `{ kind: 'rect', id?, x, y, width, height }`
- `{ kind: 'circle', id?, x, y, radius }`
- `{ kind: 'ellipse', id?, x, y, rx, ry }`
- `{ kind: 'polygon', id?, points: [{ x, y }, ...] }`

橋板必須是**有限凸多邊形**，可使用順時針或逆時針頂點。兩端需延伸到乾岸至少兩倍腳底半徑；橋板不延伸成圓頭。欄杆需以獨立 solid 定義，solid 優先，橋板不能豁免任何欄杆、岩石或花圃。

腳底接觸水面時，只有完整腳底圓盤都容納於同一橋板內才允許站立。橢圓固體會編譯為外接 64 邊形，避免曲線兩點之間漏出可站位置；可保守多擋約千分之一尺度，不會讓角色進入可見橢圓內部。

連續路段檢查將多邊形內部、每條邊的圓盤掃掠和圓形交點轉為參數區間，再由有限橋板的內縮區間覆蓋濕區。薄牆和短距離跨水都不依賴固定間距取樣。

`move()` 先做連續掃掠，再沿可行方向滑動。回傳位置除了自身合法，從原位置直線插值亦合法，避免一個網路 tick 的滑牆結果在畫面中切過轉角。作者資料在建構時複製，外部修改不會悄悄改變已快取的碰撞。

## 必須完成的整合項目

1. 地形繪圖、橋板、欄杆、花圃及全部互動物件都使用同一份具體地理資料。不得先畫完整背景再以手估曲線代表整個可站範圍。
2. `walkable` 改用 `mesh.contains`；A* 邊、捷徑平滑、手動移動及實際伺服器步進均使用 `mesh.clearSegment` 或 `mesh.move`。只在尋路時套用不夠。
3. 伺服器廣播保留安全浮點座標，或驗證量化後座標後才傳送。位置載入及重新連線須拒絕舊的非法位置並回到安全入口。
4. 瀏覽器對角色腳底插值亦做共享幾何檢查。遺失幀時不可對角穿過橋側；若插值不安全，採合法的權威位置或安全路徑。
5. 所有地面花叢／種植區都必須有對應障礙；「草地可自由走」不能暗中包含有實體高度的花圃、池塘或圍欄。

## 測試結果與發行門檻

命令：`node --test pet-app/tests/park-walkmesh.test.cjs`。

8 項獨立測試通過，涵蓋：

- 中央過橋可通行，兩側欄杆、圓頭、橋板外角與腳底懸空被拒絕。
- 橋板豁免不會越過欄杆，腳底半徑確實改變可站範圍。
- 0.1 單位薄欄杆／水縫不能穿越。
- 起終點在乾地，途中斜出橋板仍被拒絕。
- 凹水域、逆頂點順序、斜橋、圓與橢圓一致。
- 滑牆可前進，每一個回傳位置及其直線顯示路徑皆合法。
- 1,400 組固定種子對抗案例，連續掃掠再以每世界單位的細密站立檢查交叉核對；移動結果不穿水、欄杆、建築或花圃。
- 非有限座標、負半徑、破損多邊形與外部資料修改安全處理。

本機合成測量：70 個圓形障礙及一條河，10,000 次短距離掃掠約 30 ms。這只是該測試機與合成地圖的測量，不能替代整個多人場景效能檢查。

**仍需實際版本證據才能放行：**

- 每個互動入口、出生點、重連位置均可達且合法。
- 每座橋的入口、出口、四角、兩側中段，在按鍵長按、連點、斜行及點地自動走動下都合法。
- 以真正的寵物腳底位置核對 100% 顯示倍率及手機畫面；不得只看碰撞 debug 圖。
- 人為延遲／跳幀時，廣播位置與瀏覽器插值都不會把腳底放上欄杆或水面。
- 新具體地圖及其全部固體通過相同的對抗性檢查與多人瀏覽器測試。

## 2026-10-25 整合進度

已將 `park-world.mjs` 改為只從 `park-layout-v4.mjs` 取得空間資料；物件陣列只保留名稱、種類、對話及遊戲 metadata。`park-landscape.mjs` 僅為資料衍生的相容匯出，不再保留舊背景的尺寸或座標。

`COLLISION_GEOMETRY` 匯出完整 bounds、腳底半徑、水域、固體及橋板；`WORLD_SOLIDS` 包括全部橋欄杆、農作方格、景觀花圃、物件足跡、樹根及灌木。腳底半徑只由 walkmesh 套用一次。路徑以 heap A*、靜態格點與邊快取處理，手動移動、尋路平滑及逐 tick 自動移動都檢查連續掃掠。`safeVisualPosition` 提供非坐姿角色的安全插值；伺服器輸出安全浮點座標，重新加入的 cached／saved 坐標均須通過新地形檢查。

已依真實碰撞修正擋路的路牌、風鈴、蘑菇、蘋果樹、兩張長椅及家屋花圃位置。37 個互動入口、全部步道中線、30 個分散出生點均通過；37 條實際路徑共模擬 6,131 個 50ms tick，每步位置及直線顯示軌跡合法且到達目標。

新增 `park-movement-runtime.test.cjs`，透過正式 `park.js` 的移動 handler／tick 廣播配合假的 transport 檢查：拒絕欄杆目的地、長按兩側欄杆後仍輸出合法浮點位置、雙向過兩座橋、非法快取與儲存位置的重新加入、過期路徑、種植區與實際腳底半徑。這是 production handler 的封包合約檢查，並非宣稱已做實體網路延遲測試。

另發現實際美術基準問題：`PetAvatar` origin 為 0.78，而普通兔／貓／豬的第一幀可見腳底在 154/160。以樂園 scale 0.76 及圖塊縮放計，真正腳掌比 Container.y 低 34.675 世界單位；只檢查 Container.y 仍會讓腳掌出現在南側欄杆上。場景必須校正每隻角色的顯示基準，再對真正腳底進行插值及深度排序。

已準備獨立瀏覽器檢查 `scripts/test-pet-park-bridge-release-live.mjs`。它從當前 sprite frame 的 alpha 像素及 world transform 計算真正可見腳掌，檢查兩座橋的上下欄杆、四個斜行端角、乾岸出入口，並實際丟棄傳入 park:frame 3.8 秒，逐個 render sample 檢查腳掌不得出現在固體或水面；同時保存桌面／手機圖及文字實際像素尺寸。

**在上述瀏覽器腳掌與跳幀證據完成前，幾何發行驗收仍未通過。**
