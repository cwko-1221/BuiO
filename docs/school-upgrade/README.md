## 短暫斷線與提交一致性

數學整份提交及功課寫入使用伺服器操作收據，效果與回應在同一 PostgreSQL 交易內儲存；相同帳戶、鍵及內容重試返回原結果，內容不同則拒絕。中文錄音的 Blob 與其後更新答題網址的操作一起保存。

瀏覽器 IndexedDB 按帳戶保留待確認操作，最多 24 小時、40 項、40 MiB。同一資源依序傳送；暫時失敗退避重試，永久失敗保留並顯示重試按鈕。登出清除及跨分頁通知；`X-BuiO-Account` 防止另一個登入帳戶接收舊提交。這些是重要寫入的恢復保障，並非完整離線練習。

## Supabase 變更

- `server_only_data_20261010`：48 張現有 public 資料表啟用 RLS，撤回 anon/authenticated 不需要的資料表及 sequence 權限，限制 postgres 建立新表時的預設授權；新增 question-images bucket。
- `operation_receipts_20261010`：新增只有後端可讀寫的 PlatformOperationReceipts。後端使用 postgres 角色及平台 cookie 登入，沒有假設使用 Supabase Auth 的 `auth.uid()` 政策。
- `private_recordings_20261010`：程式部署及舊音檔／圖片授權讀取確認後，已關閉 recordings bucket 的 public 標記；關閉後再確認教師頁面音檔及舊圖片可正常載入。業務紀錄及舊音檔路徑不重寫。
- 遷移前核對 389 個 Storage 物件：385 個正式階段音檔、1 個歷史 done.webm、3 張題目圖片；歷史格式只允許授權讀取，新的上傳仍限制 practice／assessment。

## 索引決策

沒有採用候選 Pet payout covering index，也沒有一次加入全部缺少的外鍵索引。主要大表已有索引；小表的 Seq Scan 可以是合理計畫。

隔離的 PGlite PostgreSQL 引擎、30,000 筆合成資料、35 次讀取及每次 50 筆寫入，捨棄首五次暖機結果：

| 候選 | 讀取 p95 變化 | 批次寫入 p95 變化 | 決定 |
|---|---:|---:|---|
| 額外 studentid INCLUDE(amount) | 改善約 25.5% | 退化約 93.9% | 不採用 |
| 在現有 studentid,eventid 唯一索引 INCLUDE(amount) | 改善約 8.8% | 退化約 73.1% | 不採用 |

這些是 WASM 引擎的局部實驗，不能當作 Supabase 的效能預測。兩者均未同時達到讀取改善至少 20%、寫入 p95 退化不超過 10% 的門檻。詳細第二次結果在 `payout-index-benchmark.json`；不以額外累計金額欄位引入對帳風險。

## 驗證證據

- 根專案 `npm run check`、報表匯入、功課、Phonics、三個前端建置／Pet typecheck 通過。
- `npm run check:school-upgrade`：10 項測試，包括真實 PostgreSQL 引擎的批次順序／原子性／權限、收據、防跨帳戶讀取、快取、傳輸及管理密碼。
- 白板 Socket：12 項測試，包括 25 位學生重連、匿名拒絕及無損二進位 PNG；Buzzer 時鐘測試通過。
- 30／60 人同時登入、答題、提交及重播，在本機 JSON fixture 完成，紀錄數正確。不是生產負載測試；不是 Render／Supabase p95。
- Chrome fixture：伺服器成功但回應遺失、重新載入、十秒斷線、切換帳戶及錄音 Blob 重載恢復均通過。結果在 `load-fixture.json`。
- 科學實驗室完整瀏覽器 QA 涵蓋實驗互動、保存、手機／橫向布局及 WebGL 替代畫面；截圖存於本機 tmp。
- 模擬 1 Mbps 下載、256 Kbps 上傳、300 ms 延遲的冷瀏覽器：科學選單資源傳輸約 63 KB，不下載模型、three、physics 或 LabRenderer。這不是學校現場網速量測。
- 全部 107 項可壓縮資產約 14.55 MB，Brotli sidecar 約 3.56 MB；這是資產總量，不是每位學生首次下載量。
- 根專案及白板前端 npm audit（含 dev）均為零公告；Pet／Science 生產依賴審計亦為零。審計結果是當日快照。

## 保留的限制及後續量測

保持 Render Free、Singapore、單一實例及手動部署；沒有新增收費服務。免費閒置冷啟動仍存在。沒有在現網製造 60 人寫入壓力。

部署日誌中的 Google 中文語音暖機因未啟用供應商計費而被拒絕；升級前的部署已有相同錯誤。本次沒有啟用計費。快取改善重複請求，但不能解決供應商權限，亦不代表全部現網 TTS 流程已通過驗證。

主要暖機 API p95 改善 30%，以及兩個大型模組整體首次下載改善 30%，仍須以實際學生流程、同等快取狀態及新分段日誌量測；本次不把合成測試或單一素材縮減當成已達成整體目標。更深入的 Game 背景分段串流、Phonics 設定快取及未有代表性寫入驗證的外鍵索引保留後續評估。操作收據需要配合可接受重播期限制定清理政策，不能直接刪除仍可重播的收據。

部署及現網驗證結果另記於 `deployment.md`。資料庫權限、錄音 public 標記均可獨立還原；回退效能修改時應保留資料存取保護，避免重新公開學生資料。
