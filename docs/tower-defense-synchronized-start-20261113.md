# 塔防全班準備及同步開始

這次修正針對 2026-11-10 的 25 部 iPad 實測，以及「不要有一部分學生仍在同步，其他學生已開始」的要求。

## 最終行為

學生選擇地圖後，在老師按開始之前完成答題 session、地圖與角色素材、圖片解碼及第一幀繪圖。成功後，學生看到「戰場已準備好，等待老師與全班一起開始」，遊戲模擬暫停，老師名單才增加一個已準備學生。

老師按鈕只有在房間內每位學生都在線、已選地圖且第一幀成功後才啟用；伺服器也獨立檢查這個條件。斷線學生保留在名單，不會被悄悄扣除以變成全員已準備。學生重新整理或更換 socket 後，會取消準備狀態，待新畫面完成再確認。

老師開始時只發出即時連線訊息，不再發出答題 session HTTP 請求。各機使用伺服器共同的開始時間，預留約 1.5 秒接收訊息；加入房間時以來回時間估算裝置與伺服器時差。這能降低正常連線的開始差異，不保證斷線、背景分頁或任意網絡延遲下仍能同一毫秒顯示。

## 連線及黑屏恢復

- 正常準備直接使用已連線的 Socket.IO 通道，沿用 Don't Look Down 的連線方式，不發出額外 HTTP session 請求。即時通道不可用時才使用有 3 秒期限的 HTTP 後備；兩者使用相同 startRequestId，伺服器共用同一個同步建立函式，晚到的回覆不會另開一局。
- Socket 從簽署登入 session 取得帳戶，不能相信用戶端傳來的 studentId；同時檢查 socket 所加入房間、帳戶成員資格及房間階段。正式環境不能使用開發預覽豁免。
- 第一幀有 30 秒整體期限，涵蓋 XHR 下載後的解碼和 renderer 初始化。逾時後保留答題 session 及模擬狀態，以可重試的局部畫面恢復；重新建立場景時釋放舊 game 和未完成的 blob 圖片。
- WebGL context loss 立即暫停模擬並取消準備狀態；若 5 秒內未恢復，提供有界的自動重試，以 Canvas 重建畫面。繪圖恢復不會重新開始答題 session。
- 結束課堂會停止準備、倒數及 renderer，避免遲到的 ready callback 再蓋過結束畫面。

## 診斷與驗證

每次頁面使用一個隨機 traceId。記錄 HTTP 開始／成功／失敗、socket 後備、素材進度、第一幀、開始時間誤差及 context loss。伺服器僅接受白名單欄位和有限頻率，不記錄學生姓名、密碼、答案或完整瀏覽器資訊。最近 64 個事件同時保留在分頁的 sessionStorage，供未能即時送出的情況使用。

`npm run check:tower-defense-start` 使用隔離的 Express router、真實 Socket.IO 協議和 Chromium／Windows WebKit。25 個協議用戶中故意阻止 8 個 HTTP 回覆：17 人準備時教師不能開始，8 人經 socket 完成後才可開始；晚到 HTTP 仍取得同一 session。另檢查帳戶冒用、未登入拒絕、學生刷新、第一幀等待、共同開始時間、圖片解碼期限、GPU 中斷和 Canvas 恢復。

`node scripts/test-tower-defense-preparation.mjs --full` 額外執行既有遊戲介面回歸，涵蓋課堂開始與結束、答題、建塔拖曳、升級、售出、技能、三張地圖、橫直向、勝敗畫面及音效。

`npm run check:tower-defense` 驗證三地圖、15 波模擬、題目及遊戲規則。這些隔離測試不連正式資料庫，不是 25 部實體 iPad／學校 Wi-Fi 的容量驗收。

版本標記：`20261113-recovery-1`。對比原本 Don't Look Down，這次移除了塔防「收到老師開始後才等待額外 HTTP」的差異，並提前準備場景；沒有將 Don't Look Down 本身改成同一流程。
