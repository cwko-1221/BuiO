# 快速書寫與擦除同步修正（2026-10-31）

學生快速寫完或擦完後，老師畫面可能與學生不同。已在修正前的程式重現；這次加入兩端實際繪圖層的比對。前次驗證沒有覆蓋快速提筆及擦除後的畫面差異，這是遺漏。

## 原因及修正

- PointerUp 原本把最後座標傳給老師，卻沒有在學生畫面補畫最後一段。現在提筆時先完成本機筆畫，再送出結束事件；取消手勢使用最後有效座標。
- 本機擦膠用 CSS 像素，老師畫面與重播則用固定 800×600 座標，造成不同的擦除範圍。現在每筆保存原始畫布尺寸、固定筆刷設定與手勢 ID，直播與重播使用相同換算。
- 較舊存檔到達時，原本只保留圖片解碼期間收到的新事件；在存檔到達之前已畫上的新內容會被覆蓋。伺服器現在為事件編序，存檔分別標記包含了哪些學生操作及老師操作。老師套用存檔後，補回尚未包含的操作；不能安全套用的過舊存檔會被忽略。
- 老師擦除、學生落筆交錯時，學生歷史現在按實際操作次序分段，縮放及重新載入後仍按這個次序重播。
- 老師批改改用同一套向量擦膠，移除每次擦完傳整張圖片覆蓋學生內容的做法。手勢結束會盡快提交存檔，連續短筆畫共用存檔，正常結束提交最多每秒四次，並保持只有一個存檔等待確認。背景切換的強制提交另外處理。
- 一般及班級白板共用學生實作；兩個老師入口均套用順序、末段補畫及清空保護。

## 驗證

測試證據在 [artifacts/whiteboard-fast-sync-20261031](../artifacts/whiteboard-fast-sync-20261031/)。source-manifest.json 保存本次原始碼 SHA-256。測試使用隔離帳戶和資料庫。

- ESLint、正式前端 build、39 項單元測試通過。
- Chrome 與 WebKit 各 6 組實際 UI / Socket.IO 畫面測試：沒有 Move 的快速提筆、快速擦除、較舊存檔延遲到達、最後存檔、老師擦除與學生落筆交錯、交錯操作後縮放重播。
- 比對將兩邊繪圖層縮放至 800×600，對深色墨跡採用 1 像素鄰域容差；12 組均未發現容差外的缺筆或多筆。這不代表原始像素逐點相等，也沒有測量實體觸控延遲。修正前的 4 組案例在兩個瀏覽器都能重現差異，另保存了基線報告及截圖。
- 原有瀏覽器流程通過：兩個入口、老師批改、圖形、清空、分頁、離線落筆、確認遺失重試、延遲圖片解碼、重新連線，以及實際伺服器崩潰後恢復。
- 最新程式做了 61.1 秒混合負載：28 位學生、250ms 存檔間隔、8 位寵物遊戲玩家、登入、週報預覽及一次重啟。36658 個繪圖事件、6229 次存檔，錯誤 0；本機收發延遲 p95 5ms，RSS 最高 279.1 MiB。這是短時間回歸；10 月 30 日的 30 分鐘紀錄屬於先前版本，不能當作本次版本的長時間驗證。

執行：先 npm --prefix whiteboard-app/client run build，再 npm run check:whiteboard 及 npm run check:whiteboard-live。測試需既有 Playwright / PGlite 測試執行環境。負載可用 node scripts/test-classroom-mixed-load.mjs --seconds=60 --checkpoint-ms=250 --output=tmp/whiteboard-fast-sync-load-final。

## 發布及限制

本文件及 source-manifest.json 的驗證紀錄採集於提交前；提交與推送狀態以 Git 紀錄為準。部署時需要更新伺服器與前端，老師和學生都要重新整理頁面。尚未驗證線上部署、實體 iPad、學校 Wi-Fi 或 Render 配額。

本機 3000 連接埠的舊預覽程序（PID 28152）尚未重啟：自動審批拒絕重啟命令，只提供「blocked by policy」，沒有進一步原因。前端已編譯；完整新版本的行為在上述隔離伺服器驗證。
