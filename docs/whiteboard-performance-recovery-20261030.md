# 白板效能及課堂恢復：2026-10-30

本次處理普通白板與班級白板的繪圖、同步、程序重啟恢復，以及白板、登入、寵物對戰和周報預覽共用伺服器時的負載。這份紀錄取代「已做過多人連線測試，所以整班持續操作也已驗收」的推論。

## 實際改動

- 兩個老師畫面都改為按內容或版面變化要求一次繪製。沒有變化時不排下一個動畫幀；看不到的白板不重畫。切頁、捲動、縮放、背景和放大畫面會使相應快取失效。顯示畫布的像素比例最高為 2。
- 普通學生入口共用班級學生的同步實作，保留原本的畫筆、顏色、圖形及橡皮擦。兩個老師入口仍保留各自的控制介面及課堂類型。
- 正常同步只傳送上次確認後改變的筆畫及目前圖形，不再每 1.5 秒編碼整張 PNG。老師和學生可同時書寫，較早開始但仍在變動的筆畫也會包含在增量中。
- 同時只容許一個同步等待確認。遺失回覆會重新傳送最新內容；重新入房使用完整向量狀態修復。相同或過期序號不會重複追加筆畫。
- 超過 400 條筆畫或 10,000 點時，於完成手勢後將筆畫層合併為底圖，限制長課堂的記憶體。圖形維持獨立可編輯層。老師的橡皮擦像素校正仍可使用完整底圖。
- 伺服器以連續座標陣列保存筆畫，減少逐點物件和 JSON 欄位成本。老師繼續接收即時筆畫；有變更時每約 8 秒整合一次向量修復，避免每次確認都重送完整紀錄。
- 老師清空會變更畫面版本。學生離線期間錯過清空，重連後亦須接受新版本；延遲的老師底圖解碼和舊確認不能重新帶回已清除內容。

## 重啟恢復與保存範圍

`WhiteboardCheckpoints` 每個課堂設定及每塊學生白板各佔一列。只將有變更的部分分批寫入，預設間隔 10 秒；建立課堂時先保存設定，明確結束時先寫入結束標記。結束後清掉學生筆畫內容，保留小型標記避免舊課堂重現。

正式 PostgreSQL 使用後端資料庫連線及 RLS，沒有提供瀏覽器讀取存檔的 Data API 政策。JSON 開發模式使用與 `BUIO_JSON_DB_FILE` 同目錄的 `whiteboard-checkpoints.json`，以暫存檔及原子替換寫入。新增表的 SQL 位於 `db/migrations/20261030_whiteboard_checkpoints.sql`；後端亦會冪等建立，不需要測試程序連接正式資料庫。

程序重啟後，可恢復課堂擁有人、類型、班組設定、工作紙、鎖定狀態及學生白板。新連線仍須通過原本的登入和課堂權限檢查；其他教師不能接管原課堂。重新啟動後給老師原有的兩分鐘重連時間。冷啟動時清理超過兩小時的存檔。正在進行的搶答回合沒有跨程序重播，以免重複判分或發獎。

網絡確認代表伺服器已接收，並非每次都已寫入永久儲存。正常保存間隔為 10 秒；資料庫故障會重試。若伺服器和學生頁面同時消失，最近尚未寫入的內容仍可能遺失。若學生頁面還在，客戶端會保留比磁碟存檔更新的已確認筆畫並重新同步。

## 報表與共用資源

Excel 模組改為伺服器啟動時載入，避免課堂進行中第一個報表請求才同步載入模組。同一時段的多個班別預覽共用一次準備工作；完成後立即移除，沒有長期快取舊報表。預覽、產生報表及匯入報表共用單一工作隊列，最多八項正在處理或等候，超出時回傳可重試的 503。

這減少重複和同時工作，沒有增加伺服器 CPU，也沒有將 Excel 處理移到背景執行緒。

## 可重跑的驗證

- `npm run check:whiteboard`：同步增量、相同序號、較早的同時書寫筆畫、清空版本、舊磁碟存檔、JSON／PostgreSQL 保存、結束後不重現、擁有人權限、報表合併和隊列上限。已加入主 `npm run check`。
- `npm run check:whiteboard-live`：Chrome／Windows WebKit 的真實編譯介面、普通及班級入口、閒置重繪、筆畫、老師批改、橡皮擦、長畫面合併、分頁、遺失回覆、離線編輯、離線期間老師清空、延遲解碼、老師重載和關閉。
- 另以真實登入及兩次真正的 Node 程序中斷驗證：同一課堂恢復、比磁碟更新的本地筆畫保留、清空後再重啟仍為空白。
- `npm run check:classroom-mixed-load`：預設實際執行 30 分鐘。28 個 Socket.IO 學生持續送筆畫，8 名學生同時進行真正的寵物對戰，集中登入及六班周報預覽，14 人重連、老師重連及一次伺服器中斷。記錄畫筆與健康檢查延遲、記憶體、CPU、事件迴圈及錯誤；測試前後核對相關來源雜湊，不能在長測途中更換受測程式。

結果和截圖寫到忽略的 `tmp/whiteboard-upgrade/`；完成後將精簡報告及版本核對存到 `artifacts/whiteboard-upgrade-20261030/`。

## 額外觀察

本機正常預覽啟動時，Google 語音暖機回傳 **BILLING_DISABLED**。這是所設定 Google 專案的計費狀態回覆，未快取的新語音可能受影響；沒有核對正式網站是否使用相同設定。它不屬於白板／報表負載的成功判斷。測試啟動器現已清空相關 Google 憑證變數，避免以後的隔離測試啟動外部語音請求。

## 驗證界線

長測使用 Windows、本機真正的 Node 伺服器、Socket.IO 及隔離 JSON 資料；PostgreSQL 保存另以 PGlite 驗證。持續負載的學生是協議客戶端，瀏覽器介面另以 Chrome／WebKit 驗證。沒有把 28 個協議客戶端稱為 28 部實體 iPad。

這些測試未重現學校 Wi-Fi、正式主機的 CPU 配額或多班同時上課。持續負載包含周報預覽，報表匯出和匯入另有整合測試，沒有冒充它們已在整段長測中執行。上線前仍需要在正式資源限制下及實體 iPad 上驗收。
